# open-carpool v1.0 릴리스 노트 (develop)

> 상태: 출시 후보(RC). `main`은 기존 배포 그대로이며, v1은 `develop` 브랜치에 있습니다.
> 이 문서는 루프 라운드(보안·코드 품질·UX)가 끝날 때마다 갱신됩니다.

## 무엇이 되나요

그룹 단위 카풀 운영 PWA입니다. 매칭 앱이 아니라, 이미 함께 다니는 사람들의 "누가 언제 운전하나"를 공정하게 돌리는 도구입니다.

- **로그인**: Google, 이메일 링크, Kakao(OIDC, 기능 플래그). 카카오톡 인앱 브라우저 감지와 외부 브라우저 안내.
- **그룹**: 3단계 생성 마법사, 초대 코드·링크·QR, 코드 재발급, 역할(소유자/관리자/멤버).
- **프로필**: 동네(대략적 위치), 요일별 출퇴근 시간, 운전 가능 여부와 좌석, 차량 끝자리(부제용).
- **크루**: 제안·수락, Fagin-Williams 공정 순번(정수 단위 장부, 1~6인), 다음 운전자 강조.
- **주간 계획**: 자동 배정, 마감 시간 전 불참·운전 못 함·자원 운전, 탑승자 확인 후 한 번에 운행 완료 → 장부 반영.
- **비용 정책**: 한국은 순번제만(유상운송 회피), 그 외 지역은 실비 분담 기록.
- **부제(번호판 요일제)**: 정책 배지와 부제 짝꿍 찾기.
- **관리자**: 참여율·운행 수·좌석 이용률 대시보드, 월별 CSV(엑셀용 BOM).
- **공유**: 주간 계획 공유(Web Share, 복사 대체), 저녁 요약 배너.
- **지도**: 한국은 Naver, 그 외 Google. 내비 앱 딥링크.
- **행사 카풀 보드**: 차 등록, 타기/내리기, 남은 좌석.
- **이탈 감지**: 최근 4주 참여 감소 시 크루장에게 배너.
- **다국어**: 한국어/영어.
- **라이선스**: AGPL-3.0, 자체 호스팅 문서(`docs/SELF_HOSTING.md`), 개인정보처리방침·이용약관 템플릿(`docs/legal/`).

## 검증 방법

| 항목 | 명령 | 마지막 결과 |
|---|---|---|
| 타입 검사 | `npm run lint` | 0 errors |
| 단위 테스트 | `npm test` | 32 files / 200 tests |
| 보안 규칙(에뮬레이터) | `npm run test:rules` | 8 files / 104 tests |
| 빌드 | `npm run build` | exit 0 |
| 실제 브라우저 E2E | `E2E_VIEWPORT=mobile|desktop bun scripts/e2e/crew-slice.ts`, `admin-events-slice.ts` | 각 10/10 |

E2E는 Firebase 에뮬레이터 위에서 두 사용자(서로 다른 origin)로 이메일 링크 로그인 → 그룹 생성 → 초대 링크 가입 → 크루 생성·수락 → 순번 운전자 표시 → 운행 완료 → 장부 ±0.5 → 관리자 CSV → 행사 보드까지 확인합니다.

## 루프 라운드 요약

- **보안(G003)**: 18건 발견. 네이버 프록시에 Firebase ID 토큰 검증, 장부 변경을 운행 정산에 결합(Fagin-Williams 배분을 규칙에서 검증), 크루 수정 분리, 운행 생성 형태 제한, CSP 등 보안 헤더, 개발 프록시의 토큰 전달 차단. 모든 수정은 실패하는 테스트를 먼저 작성.
- **코드 품질(G005)**: 11건 수정. 계획 저장을 트랜잭션으로(동시 불참·자원 운전 유실 방지), 크루를 떠난 탑승자가 있는 운행 완료, 삭제된 요일 운행 취소, 운전자 가로채기 방지, 이중 탭 방지, 마감 시계 갱신, 롱폴링 자동 감지.
- **UX·접근성(G004)**: 45건 발견, 수정 진행 중.

## 알려진 제한

- 백그라운드 푸시 알림은 서버가 필요해 v1에는 없습니다(앱이 열려 있을 때의 로컬 알림만).
- App Check와 네이버 프록시 요청 횟수 제한은 미적용(`docs/ARCHITECTURE.md` 후속 과제).
- CSP는 실제 Vercel 배포에서 아직 검증하지 않았습니다. 커스텀 Auth 도메인을 쓰면 `frame-src`에 추가해야 합니다.
- 부제 정책이 바뀌어 계획된 운전자가 그날 운전할 수 없게 되면, 관리자 클라이언트가 다시 계획할 때까지 일반 멤버의 재계획이 규칙에서 거부됩니다.
- 관리자 통계 기간은 30일 고정입니다. 행사는 모든 멤버가 만들 수 있습니다.
- 파일럿 그룹은 아직 정하지 않았습니다(사용자 결정 대기).

## 배포 전 체크리스트

1. Firebase 프로젝트 생성, Auth 공급자(Google·이메일 링크) 활성화, 승인 도메인 추가.
2. `firebase deploy --only firestore:rules,firestore:indexes`.
3. Vercel 환경 변수: `VITE_FIREBASE_*`, `FIREBASE_PROJECT_ID`, `VITE_NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`.
4. 배포 후 브라우저 콘솔에서 CSP 위반이 없는지 확인.
5. `develop` → `main` 병합은 사용자가 결정합니다.
